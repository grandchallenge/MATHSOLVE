## Purpose

Construct a complete exact search design for six-state, two-symbol blank-tape Turing machines under the protected H2 evaluator. Every symmetry reduction and every pruning rule used to exclude candidates must have a replayable soundness argument.

This package exists because WP01 established scorer concordance but did **not** establish the proposed search normalization as exact.

## Fixed facts from WP01 adjudication

Accepted:
- protected evaluator semantics for regular `solution.json` payloads;
- baseline replay: `steps=6`, `ones=6`, `tape_span=7`;
- every valid witness executes at least six transitions;
- private budgets reconstructed from protected locks:
  - validation: `250000`;
  - test: `1000000`.

Explicitly not accepted:
- fixing `transitions.A.0 = [1,"R","B"]` as WLOG;
- local-hash, blank-ray, or macro-simulation pruning as exact without proof;
- promotion of the WP01 seeded 32-step witness.

A concrete counterexample to the rejected first-write normalization is a valid six-step machine whose first transition writes `0` and moves to `B`.

## Exact objective

Produce an exact-search construction with all of the following properties:

1. **Complete candidate space.** Define the full 12-entry machine space and the exact equivalence relation used for symmetry quotienting. State which transformations are genuine symmetries of the fixed blank-zero model and prove that every excluded representative has an included equivalent representative.

2. **Canonical enumeration.** Give a deterministic enumeration or partial-table search procedure that reaches every equivalence class admitted by the proof. State the ordering, branching rules, and completion rule precisely enough to implement independently.

3. **Exact pruning ledger.** For every rule that discards a partial or complete machine, provide:
   - formal predicate;
   - proof of soundness;
   - minimal replay witness or test;
   - explicit statement of whether the rule is exact or heuristic.
   Heuristics may prioritize search order but must never remove candidates.

4. **Cycle/non-halting handling.** Any exact early non-halting rejection must be justified by a full future-equivalence argument. Hash collisions, finite local windows, translated configurations, or macro summaries are insufficient unless the retained state is proved complete for future behavior.

5. **Dual replay.** Implement or specify an independent scorer compatible with the accepted WP01 semantics and replay any promoted candidate through both:
   - the independent scorer;
   - the protected evaluator semantics.
   A candidate is promotable only if both produce the same exact metrics.

6. **Bounded execution.** Run a bounded search tranche if computationally practical. Record the search bounds, number of canonical nodes/candidates visited, all exact pruning counts, seed if any randomized ordering is used, and the best exact witness found. A search result is secondary to correctness of the exact design.

## Completion gate

WP02 is complete only when the return contains either:

- a replayable exact-search design whose completeness and pruning soundness are established, together with exact bounded-run evidence if executed; or
- one precise blocker/counterexample that demonstrates why the proposed exact design cannot yet be trusted.

No search heuristic may be represented as an exact exclusion rule.

## Claim boundary

This work package does not ask for the exact value of `S(6)`, does not establish a world record, does not authorize AutoLab submission, and does not create GCL or MATHCERT certification.
